# File Handling Policies for AI Agents

This document provides guidelines for AI agents on how to handle files and directories within the Edu-AI project. Adherence to these policies ensures consistency and maintainability.

## General File Handling

*   **Read Before Modifying:** Always read a file's content before making any modifications. Ensure you understand its purpose and current state.
*   **Consistency:** Maintain consistent code style, formatting, and naming conventions throughout the project. Refer to the project's coding standards documentation (if available).
*   **Idempotency:** Aim for idempotent changes where possible, meaning that applying the same change multiple times should have the same effect as applying it once.

## Special Files and Directories

### Configuration Files (`.config`, `*.properties`, `*.xml`, etc.)

*   **Purpose:** These files store application settings, build configurations, or environment-specific parameters.
*   **Handling:**
    *   Be cautious when modifying configuration files. Understand the impact of each change.
    *   Prefer using environment variables or build flavors for environment-specific settings over hardcoding in config files, unless the file is intended for such specific configurations.
    *   Ensure that sensitive information (API keys, passwords) is not committed directly into version control. Use placeholders and secure methods for managing secrets.

### Resource Files (`res/` directory in Android projects)

*   **Purpose:** Contains UI elements, strings, drawables, layouts, etc.
*   **Handling:**
    *   Follow Android resource naming conventions.
    *   Ensure drawables are provided in appropriate resolutions (mdpi, hdpi, xhdpi, etc.).
    *   Externalize strings into `strings.xml` for proper internationalization.

### Build Scripts (`build.gradle`, `build.gradle.kts`, `settings.gradle`)

*   **Purpose:** Define project structure, dependencies, build settings, and tasks.
*   **Handling:**
    *   Use `gradle_sync()` after making changes to build scripts.
    *   Be mindful of dependency versions and compatibility. Use `version_lookup` to check for the latest stable versions.
    *   Ensure any new dependencies are added with appropriate configurations (implementation, api, testImplementation, etc.).

### Test Files (`*Test.kt`, `*Test.java`, `androidTest/`)

*   **Purpose:** Contain unit tests, integration tests, and UI tests.
*   **Handling:**
    *   Write clear, concise, and maintainable tests.
    *   Ensure tests cover edge cases and different scenarios.
    *   Run relevant tests before committing changes. Use `gradle_build("app:testDebugUnitTest")` for unit tests and `gradle_build("app:connectedDebugAndroidTest")` for instrumented tests.

### Generated Files (e.g., `R.java`, generated code from annotation processors)

*   **Purpose:** These files are automatically generated by the build system or other tools.
*   **Handling:**
    *   **DO NOT** manually edit or commit generated files. They will be overwritten.
    *   If you need to modify the behavior controlled by generated files, you should modify the source files that cause their generation (e.g., layout XMLs, data classes, annotation processors).

### Special Directories

*   **`docs/`:** Contains project documentation. Add any new documentation files here.
*   **`assets/`:** Contains raw file-asset data. Handle with care, as these are often embedded directly into the app package.
*   **`bin/` or `build/`:** Intermediate build output. These directories should generally be ignored by version control and should not be modified.

## AI Agent Interaction Guidelines

*   **Respect File Permissions:** Do not attempt to modify files or directories that are read-only or should not be altered (e.g., generated files, build output).
*   **Purposeful Modifications:** Ensure every change made to a file has a clear purpose and aligns with the project's goals.
*   **Documentation First:** When introducing new components or significant logic, create corresponding documentation in the appropriate directory (e.g., `docs/`).
